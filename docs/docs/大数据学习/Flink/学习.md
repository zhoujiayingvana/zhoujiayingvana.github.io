常见问题：如何在不丢失应用状态的前提下更新作业的程序代码？或者跨flink集群的作业迁移？

用savepoint主动保存作业，更新代码，然后恢复  
**关键点：**  
新 SQL 必须与旧作业的算子拓扑保持兼容，否则无法恢复状态。

比如：

✅ **允许的修改（不会破坏状态）**

+ 修改 filter 条件、where 逻辑；
+ 修改 select 中的字段；
+ 修改 UDF 内部实现；
+ 调整 sink 输出逻辑；
+ 加入 stateless 的计算列。

❌ **不允许的修改（会导致状态不兼容）**

+ 改变聚合结构（如从 `SUM` 改成 `AVG`）；
+ 增减窗口定义（例如改 `TUMBLE` 窗口长度）；
+ 增加或删除 Join；
+ 修改 keyBy 字段；
+ 修改分组键（group by）；
+ 改变并行度但未设置 maxParallelism。
